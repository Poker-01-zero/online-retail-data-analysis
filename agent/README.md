# 电商分析 Agent

在原有 SQL 分析和复购预测之上，增加自然语言取数入口。第一版通过模型自主选择工具、读取真实结果、处理错误并作答；使用 DeepSeek 工具调用接口与 Python 标准库实现，支持命令行和本地网页。

## 能做什么

| 工具 | 作用 | 数据边界 |
|---|---|---|
| `monthly_metrics` | 月度或连续月份的营收、订单数、加权 AOV | SQL 导出，全体国家含匿名订单 |
| `compare_years` | 两年相同月份的同比 | 默认拒绝含不完整月的比较 |
| `segment_summary` | RFM、商品 ABC、帕累托 | 仅全期汇总，不能按国家或年份筛选 |
| `customer_list` | 概率名单或召回候选优先级名单 | 仅 2011-08-31 历史观察点，1–50 人 |
| `model_report` | 三窗口两模型 AUC、概率名单提升度 | 离线评估，不代表营销增量 |
| `metric_definition` | 指标定义、清洗差异、因果边界及能力范围 | 维护的项目口径字典 |

例如：

- “比较 2010 与 2011 年 1 至 11 月的营收、订单数和客单价同比。”
- “全期 RFM 重要保持客户有多少人？”
- “列出 2011-08-31 召回优先级最高的前 5 名客户。”
- “那改按复购概率排，只要前 3 名。”（网页支持连续对话）
- “W3 提升度是多少，能证明发券有效吗？”

## 运行

**Windows 快速启动：双击项目根目录 `start_agent.cmd`。** 它会准备查询快照、启动服务并自动打开浏览器；使用期间保持终端窗口打开。不要直接双击 `agent/index.html`，它只是前端文件，不能单独执行查询。正确地址是 `http://127.0.0.1:8765/`。

从仓库根目录运行，Agent 本身无额外第三方 Python 依赖。Windows 若 `python` 不在 PATH，用 `C:\Users\lenovo\anaconda3\python.exe` 替代。

```bash
# 1. 用仓库内已有的7个导出文件建立只读查询快照，不需要重跑106万行CSV
python -m agent.build_db

# 2. 配置模型（见下文）后，实际提问
python -m agent.run --question "2011年前11个月销售额同比怎么样？"
python -m agent.run --question "W3逻辑回归AUC是多少？" --json

# 3. 本地网页，浏览器访问 http://127.0.0.1:8765
python -m agent.web
```

复制 `agent/.env.example` 为 `agent/.env`，填写 `AGENT_API_KEY`；默认 `AGENT_BASE_URL=https://api.deepseek.com`，`AGENT_MODEL=deepseek-flash`。如果已配置同一官方服务的 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_AUTH_TOKEN` 环境变量，可直接复用，不读取或复制 Claude Code 配置文件。

**GitHub 分发采用使用者自备 Key。** 仓库只提供空的配置模板；下载者在自己的电脑填写自己的 `agent/.env`，调用计入其自己的模型账户。仓库不包含作者密钥，也不内置作者的远程代调用服务。若将来作者用自己的 Key 部署公网后端，所有访问该后端的调用才会计入作者账户；当前版本仅在本机运行。

实际模型调用会发送问题、工具定义、会话上下文及选中的查询结果到配置的模型服务；原始 CSV 和未注册的其他本地文件不在工具可访问范围内。密钥只在服务端使用，不返回网页或写入调用记录。模型调用可能产生费用。

网页仅绑定本机 `127.0.0.1`，不作为公网服务部署。运行时数据库、`.env` 和 CLI/网页调用记录在 `.gitignore` 中排除。SQL/ML 导出更新后必须重新运行 `agent.build_db`；启动时会用 SHA-256 检查快照与源文件的一致性。

## 架构与取舍

```text
自然语言问题 / 最近6轮会话
    → DeepSeek选择工具及参数
    → 参数类型、枚举、日期前置条件、条数上限检查
    → 固定参数化SQL → 只读SQLite分析快照
    → 工具结果/错误反馈给模型
    → 模型解释 + 程序附加来源与准确的客户明细
```

- SQLite 是 MySQL 已导出分析表和 ML 结果的本地查询副本。当前版本通过预定义工具访问已有导出结果，不直接连接 MySQL，也不支持任意 Text-to-SQL 或工具范围之外的取数。
- 模型可以选择多个工具，收到错误后可以修正参数；每个问题最多 6 轮、12 次工具调用，每次接口请求超时 45 秒。
- SQL 文本固定，模型只提供受校验的业务参数；SQLite 用 `mode=ro` 和 `query_only` 双重只读。不向模型提供文件、shell 或发券工具。
- 模型不得擅自把英国查询改成全量查询，或把今天的名单改成历史名单。业务前置检查也会拦截缺少年份/月份范围的取数；这是基本启发式校验，不能保证所有复杂自然语言都理解正确。
- 客户名单由程序按工具结果展示，避免模型改写 ID、金额或重排。概率取自导出文件的四位小数，并列按客户 ID 升序；1.0000 不能解释为保证复购。
- `priority` 是历史消费金额 × 90 天未复购概率的启发式候选池；`probability` 才是按复购倾向排序。前者的触达收益未验证，后者的 Lift 也不能证明发券有效。
- SQL 历史清洗与 ML 时间戳清洗的差异沿用项目说明，不在 Agent 中重新解释成逐笔精确匹配。

接口实现参考：[DeepSeek Tool Calls 官方说明](https://api-docs.deepseek.com/guides/tool_calls/)。

## 验证与实测

```bash
# 离线工具、参数边界、调用循环及业务前置检查
python -m unittest agent.test_agent -v

# 以下调用真实模型；不会用模拟结果替代模型评测
python -m agent.evaluate --output agent/outputs/eval_release.json
python -m agent.evaluate --cases agent/eval_holdout.json --output agent/outputs/eval_extra_release.json
```

2026-11-10，`deepseek-flash`，最终版本的一次实测：

| 检查 | 结果 |
|---|---|
| 离线单元测试 | 本轮增补后16项，通过 |
| 24 道固定开发回归题 | 24/24 通过；中位耗时 2.541 秒，P95 4.034 秒 |
| 额外 8 道变体题 | 8/8 通过；中位耗时 2.864 秒，P95 4.266 秒 |
| 网页 | 本地回放已保存评测结果：提交、来源与工具记录、重置会话、窄屏布局通过 |
| 网页真实联调 | 完成2道连续问题，浏览器→本地服务→DeepSeek全链路通过；同比、名单顺序、来源及网页响应无密钥检查通过 |
| 本地请求边界 | 外站 Origin 的 API 请求返回 403 |

**以上结果仅反映有限题集的通过率，不代表任意问题的准确率。** 固定题集用于开发与提示词迭代；8 道额外题也不足以证明泛化能力。评分检查回答状态、成功工具、部分参数、指定数字、边界关键词和客户顺序，未覆盖所有自然语言语义，不用 LLM 裁判。代码本身也不能全面验证自由文本回答中的因果推断。

完整记录在 `outputs/eval_release.json` 和 `outputs/eval_extra_release.json`，含各题回答、工具调用、参数、查询结果、来源哈希、耗时和 token 用量。评测记录只含公开数据集的衍生结果；真实业务部署时应另做脱敏。

本轮验收另抽查6题，通过6/6，记录在 `outputs/acceptance_final.json`，题目位于 `eval_acceptance.json`。其中新增了“分年RFM不得擅自用全期替代”的程序拦截与单测。下载者隔离复现检查见 `outputs/distribution_check.json`。项目实现范围与核验记录见 [`验收记录`](../验收记录.md)。

开发过程的失败也保留：首轮 `eval_v1_initial.json` 为 21/24，存在擅自补充全量结果、替换历史日期等问题；`eval_final.json` 为 23/24，存在缺少年份时自行猜测的问题。后续增加了范围约束、日期前置检查和客户明细程序化展示。未只挑选成功题目汇总。

页面布局检查使用拦截请求的本地回放。2026-11-10 完成两道连续问题的真实模型联调，记录见 `outputs/web_live_check.json`，页面截图见 `outputs/demo-live.png`；两题耗时分别约2.73秒、2.86秒。模型调用使用本机配置的账户，其他使用者需自行配置。

## 查询示例与结果核对

1. 查询两年同期经营指标，核对年份、月份、营收、订单数和 AOV。
2. 查询历史候选名单，核对观察日、排序方式、客户顺序和返回条数。
3. 查询模型评估与指标定义，区分离线复购排序表现和未经验证的营销增量。

网页展示来源和工具调用记录，可据此核对参数、查询结果和最终回答。当前版本用于本地历史数据查询，不提供营销触达或线上策略执行。

## 文件结构

```text
agent/
├── data.py / build_db.py    导出文件 → SQLite，只读连接与源文件校验
├── tools.py                六个业务工具及口径字典
├── provider.py             环境变量配置和模型API适配
├── runtime.py              工具调用循环、前置检查、客户明细展示
├── run.py                  命令行入口
├── web.py / index.html     本机网页演示
├── test_agent.py           离线测试
├── eval_cases.json         24道开发回归题
├── eval_holdout.json       8道额外变体题
├── evaluate.py             真实模型评测
├── outputs/                实测报告、页面回放截图
├── data/                   本地数据库，忽略
└── traces/                 本地问答调用记录，忽略
```
